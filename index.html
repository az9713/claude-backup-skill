backup-claude

A Claude Code skill that copies the Claude Code and Claude Desktop setup into one zip file and restores that zip on a new Windows laptop. Written 2026-10-17. Source: github.com/az9713/claude-backup-skill.

1. What the skill does

The skill has two PowerShell scripts in %USERPROFILE%\.claude\skills\backup-claude\scripts\.

  • backup.ps1 runs on the old laptop. It writes one zip and two receipt files to D:\backups\claude. It creates the folder if it does not exist.
  • restore.ps1 runs on the new laptop. It unpacks the zip and merges the files into the user profile and into %APPDATA%\Claude.

Each run writes three files with the same name stem, claude-backup-<COMPUTER>-<yyyyMMdd-HHmm>:

FileContent
.zipThe backup. The zip also holds claude-backup-manifest.json, which records the user name, profile path, computer name and date of the backup.
.files.txtThe receipt: one line for each file that the script wrote into the zip.
.skipped.txtEach file or folder that an error kept out of the zip, with the Windows error text. If nothing failed, it says No files skipped.

Commands

# Back up (old laptop). Claude Code can stay open.
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\skills\backup-claude\scripts\backup.ps1"

# Restore (new laptop). Close Claude Code and Claude Desktop first. Use a plain PowerShell window.
powershell -ExecutionPolicy Bypass -File restore.ps1 -Zip D:\backups\claude\claude-backup-<COMPUTER>-20261017-2149.zip

If Windows gives the USB drive a letter other than D:, add -Dest <letter>:\backups\claude to the backup command. restore.ps1 is in the zip at .claude/skills/backup-claude/scripts/restore.ps1. Copy it out of the zip before you run it.

2. How the backup works

  1. Make the destination folder. New-Item -ItemType Directory -Force creates D:\backups\claude and any missing parent folders.
  2. Choose the sources. From %USERPROFILE%: .claude\, .claude.json and AGENTS.md. From %APPDATA%\Claude: a fixed list of 12 config files and session folders (section 4). The script ignores a source that does not exist.
  3. Walk every folder. The script reads each folder itself. It does not use tar.exe (section 3). It does not go into the 8 excluded .claude folders and files (section 5).
  4. Follow links. A symlink or a junction is copied as the real files that it points to. 69 skill folders are junctions: 66 into %USERPROFILE%\.agents\skills, 2 into %USERPROFILE%\.codex\skills, 1 into a folder under %USERPROFILE%. If a link points to its own parent folder, the script records it in .skipped.txt and does not follow it, because following it would repeat without end.
  5. Read files that are in use. Each file is opened with share mode ReadWrite, Delete. Thus the script can also read the transcript that a running Claude Code session writes. Only a file that another program locks exclusively fails, and that failure goes into .skipped.txt.
  6. Write the zip. The script uses the .NET System.IO.Compression.ZipArchive class with CompressionLevel.Fastest. It writes one entry for each file, keeps the file's last-write time, and stores non-ASCII names correctly.
  7. Write the receipts. .files.txt and .skipped.txt are UTF-8 text files.
  8. Check the finished zip. The script opens the zip again. It stops with an error if .claude/settings.json or .claude.json is missing. It warns if the number of entries in the zip is different from the number of lines in .files.txt.

3. Why the scripts do not use tar.exe

The first version used the Windows tar.exe (bsdtar 3.8.9). On 2026-10-17 it made a zip of 8,887 MB that was not complete. A comparison of that zip with the files on disk showed:

  • 615 Claude Desktop files were missing, and 613 of them came from one Cowork session (local-agent-mode-sessions\<session-id>). One unreadable link (debug/latest) in that session gave the error Cannot stat: Invalid argument. After that error, tar did not copy the rest of that folder and gave no message about the missing files. Its only signal was exit code 1.
  • In a test, one locked file made tar leave out 3 other files in the same tree.
  • A file named 日本 ✓.txt made tar crash with exit code -1073741819 (access violation), and the zip was empty.

The .NET version adds files one at a time and records each failure. Thus each file is in .files.txt or in .skipped.txt, and no file can be lost without a record.

6. Why these files are enough to recreate the setup

Claude Code and Claude Desktop do not keep their setup in the Windows registry or in a cloud copy. They read it from a fixed set of files in the user profile. If those files are on the new laptop at the same paths, the new installation reads the same setup. The table connects each part of the setup to its file and shows that each file is in the zip.

Each item in section 5 belongs to one of three groups: (1) the app makes it again, (2) the app or its installer downloads it again, or (3) Windows encrypts it to the old machine, so a copy would not work. None of the three groups holds a setting that you made.

Evidence. In a test, I set USERPROFILE and APPDATA to test folders and did a full backup and restore. The test checked these points:

  • excluded folders were left out
  • a junction to a skill was followed
  • a file in use by another program was read
  • a non-ASCII file name (日本 ✓ café.jsonl) came back with the correct content
  • the restore copied the new laptop's existing settings.json aside before it replaced the file

The only absolute file path in your settings.json is ~/.claude/statusline-command.sh, and that file is in the zip.

7. Conditions and limits

The argument in section 6 is true only when the conditions below are true. Read them before you start a migration.

MCP servers need their programs

The zip holds each MCP server's configuration, but not the program that the configuration starts. 8 of the 9 user MCP servers in .claude.json use a local command, and you must install that command on the new laptop:

  • 1 command-line tool installed with Bun, in %USERPROFILE%\.bun\bin
  • 1 Python virtual environment inside a project folder under %USERPROFILE%\Downloads
  • 1 executable that a desktop app installs under %LOCALAPPDATA%\Programs
  • 1 command-line tool in %USERPROFILE%\.local\bin
  • 2 Node.js scripts: one in a global npm package under %APPDATA%\npm\node_modules, one in a project folder under %USERPROFILE%\Downloads
  • 2 servers started through npx and uvx, which need Node.js and uv

The 9th server is an HTTP server and needs nothing installed. The one MCP server in the Desktop config uses the same Node.js script as one of the Claude Code servers.

3 plugin marketplaces are local folders

19 of the 22 marketplaces come from GitHub, and Claude Code downloads them again. The other 3 point to project folders under %USERPROFILE%\Downloads, which are not in the zip. The zip has the cached copy of those plugins in .claude\plugins\cache\. To update or reinstall those plugins, you need the source folders.

Same user path

The session folder names (.claude\projects\C--Users-<user>-…), the 987 project paths in .claude.json, and the MCP paths above all contain the old profile path C:\Users\<user>. If the new laptop's profile path is different, restore.ps1 shows a warning, and you must change these paths yourself.

Not in the zip

  • Project-level .claude\, CLAUDE.md, .mcp.json and HANDOFF.md. They are in each project folder.
  • 2 personal knowledge folders in %USERPROFILE% that are not part of Claude (2,898 MB, and one git repository).
  • claude.ai web chats. They are on Anthropic's servers. To get a copy, use claude.ai → Settings → Privacy → Export data.

Other points

  • Linked skills come back as plain folders. After a restore, the 69 linked skill folders are normal folders and no longer junctions into .agents\skills. Tools that update .agents\skills (for example npx skills) do not update them.
  • The zip is not encrypted. It holds .credentials.json and the API keys in the MCP env blocks. Keep it on the local USB drive. Do not put it in cloud storage.
  • The backup holds only what exists on the day of the run. Your cleanupPeriodDays is 10000, so Claude Code does not delete old transcripts within that time.
  • No restore on a second laptop has been done. The proof in section 6 comes from the file mapping and the test-folder round trip. To prove it fully, restore the zip into a second Windows user account or onto the new laptop, and start Claude Code there. A second account also has a different user path, so that test also shows the path warning.

8. How the restore works

  1. Check that Claude is closed. The script stops if any process named claude runs. It only checks for the process. It never stops a process.
  2. Unpack the zip. The .NET ZipFile.ExtractToDirectory unpacks the zip to %TEMP%\claude-restore-<stamp>. If the unpack fails, the script stops before it changes any file.
  3. Compare the user path. The script reads claude-backup-manifest.json. If the old profile path is different from the new one, it shows a warning.
  4. Copy existing items aside. Before it replaces an item, the script copies the current version to %USERPROFILE%\claude-pre-restore-<stamp>\.
  5. Merge the backup. robocopy /E copies the folders, and Copy-Item copies the single files. Files with the same name are replaced. Files that exist only on the new laptop stay.
  6. Clean up. The script deletes the temporary folder. Then start Claude Code. If it asks you to log in, run /login.
